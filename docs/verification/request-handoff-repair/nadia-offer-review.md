# Optional household offer handoff: end-to-end review

## Defect and ownership
The game exposed guest-kennel acceptance without an offer and let the collar controller fit an available collar without checking a current offer. These are game-file defects. The shared worker response writer separately hard-coded cat arrangements and mastery into every optional NPC decision. That writer must become neutral before testing Nadia's existing collar/kennel choices against it.

## Repair
Local game controllers bind pending offers to the current player, body and space; require the actual available collar or unoccupied living-room kennel; keep preparation separate from NPC offer and player acceptance; and recheck resources at resolution. Menu and typed canine requests share the same controllers and modality guards. Conversation creates no new offer. A failed or stale model response cannot create acceptance controls. Removing ordinary gear affects only its corresponding restraint; a guest and Dart cannot occupy the same closed kennel. Existing mastered release remains available. No new curse, ownership, duration, price or permission is introduced.

Worker v11 only replaces the cat-specific optional-response task with the supplied actor/choice/terms. It keeps mastery instructions conditional on the actual choice. Protocol, model, sampling, credentials, budget, transport and ordinary completed-result writing remain unchanged. The worker does not execute game actions.

Desktop browser checks exercise pending/refusal/offer/typed acceptance and reload using simulated replies. Phone browser verification is tracked separately and not yet claimed here.
