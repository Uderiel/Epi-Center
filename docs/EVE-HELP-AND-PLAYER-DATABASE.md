# Eve help and learned-information database — local, unpublished

Eve’s already-approved remote-help role is implemented through A.S.S. from any gameplay location: “Eve, how do I …?”, “help”, and similar explicit help requests. This route supplies contextual guidance from actual currently offered actions. It does not accept a quest or create physical Eve presence. The AI context distinguishes remote communication from holographic projection: no projection outside the Spire outer ring. Existing identity/presentation rules remain. Private form thoughts and player-to-player channels do not silently become external NPC speech.

`player-guide.js` maintains knowledge per stable player ID. Confirmed NPC dialogue is retained as attributed statements, not automatically verified truth. Player assertions, private form thoughts and remote-help boilerplate are excluded. Actually known apartment occupants, visited locations and owned forms are derived from authoritative existing records. Learning is recorded when feed entries arrive, so later feed truncation does not erase already captured knowledge. Retained old feed/known records backfill the database; previously discarded history cannot be reconstructed.

Say “show my database”, “open the codex”, or “search database for Priya”. Help and Database buttons are optional shortcuts to those same handlers. No private source dossier, undiscovered NPC home, hidden role or unowned form is imported just because it exists in canon. The database is owner/player reference material, not a dump into every AI prompt.

The legacy source was searched before implementation; existing Eve approved lore/help rules and authored answers were reused. This is a new durable adapter over current actual knowledge, not a claim to have recovered a complete historical legacy database.

Verified with isolated save/player tests and actual browser composer/reload checks. No owner saves, paid model calls or publication were used.
